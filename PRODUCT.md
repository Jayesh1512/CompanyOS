# CompanyOs · Product

<!-- impeccable:product-schema 1 -->

CompanyOs is a local agent workspace for company setup, approved knowledge, customer care and versioned operational improvements. **Start demo** opens a fresh fictional customer-care agency; the [AI demo page](docs/REAL_AI_DEMO.md) provides separately configured owner-funded encrypted inference.

## Platform

web

## Stack

Node ESM, browser JavaScript, a durable private journal, M01 Rules, M03 Treasury and native JBrain. A Rust NEAR audit contract is deployed on mainnet and has recorded Agent API writes. Official Cloud, 1Click and Agent API SDKs provide the supported integration paths.

## Users

Company owners define purpose, operating boundaries and approved knowledge. Agents receive scoped assignments and versioned context. Customers use the separately scoped customer-care portal. Northstar Care and Harbor Mutual Insurance provide the fictional example company and client.

## Product Purpose

**Let an owner define a company, supervise work and carry tested improvements into future tasks.** The operating model is objective → manager → scoped specialist → result → observed gap → backlog → developer → fixed evaluation → version promotion. Controlled full-loop tests exercise this chain with real application storage, Rules, Treasury and native JBrain.

Agent-managed operation is the default for new companies. Owner-managed operation retains owner-managed team assembly. Owners set policy, budget, document grants and exceptional decisions.

## Operating Context

The main workspace uses port **4173**. Its top-right **Start demo** button creates a separate agency with its own identity, four agent profiles, four fictional native JBrain policy documents and two local customer-care listings. Customers receive cited source excerpts and persistent owner-review tickets. Each new launch creates a fresh agency, while earlier session files remain on disk. [Demo walkthrough](docs/LOCAL_REAL_DEMO.md).

The [AI demo](docs/REAL_AI_DEMO.md) uses a saved company agent and selected documents. Two recorded owner-funded calls produced a verified cited answer and an escalation ticket, with provider bills totaling **$0.00322116**. SDK verification occurs during the original encrypted call. Accepted results persist in the application journal.

## Capabilities

Unified setup follows Define company → Review agents → optional Company brain → Boundaries & infra → Review & finish. Saving the brief creates persisted, paused manager/backlog profiles through Rules-defined roles. Owners edit profile names, roles, instructions and written skills. Finish records configuration review; Start uses the current execution scope and readiness.

Operations shows objectives, assignments, actual run states, improvement proposals, resource requests, service drafts and lifecycle history. Journal-backed work uses durable leases, fences, stable effect identities, counters and dependency checks.

Native JBrain holds company documents. Agents use explicitly granted, selected revisions with bounded excerpts and content hashes. Import previews support selectable-text PDFs, UTF-8 text and public webpages. Explicit Save commits reviewed text and provenance. Saved data and history persist locally.

Automatic template improvements add or require allowed fields in registered structured templates. The fixed evaluator runs baseline and candidate against the same mandatory cases. M01 checks exact hashes and the current head before promotion. Rollback creates another immutable revision. Instruction changes use paused owner review and apply to the named agent’s future context.

The marketplace groups inference descriptions, knowledge resources, written skills, independently authored SOUL.md guidance, external-service descriptions and wallet setup information. Exact content versions reach future context. Local customer-care listings lead to private conversations and approved fictional policy excerpts. Separately invoked x402 task purchases have retained completed-task outputs.

The application’s shared financial store records exact M01 plans through M03. The configured **USD5 actual-plus-pending ceiling** covers that store’s admitted effects. Standalone evidence scripts retain separate run records and operator-selected amounts.

The NEAR ledger commits ordered event hashes. Recorded mainnet evidence includes deployment, scoped-key writes and Agent API native-call appends. Read tools inspect public state; export and preparation produce safe unsigned batches. Mainnet evidence runs use separately invoked scripts. [Ledger implementation](docs/NEAR_ONCHAIN_LEDGER.md).

## Product Principles

- Lead with the objective, responsible agent, result and next action.
- Keep authority and exact financial plans in the journal-backed Rules/Treasury path.
- Make persistence, revision history and source citations visible.
- Label local execution, controlled tests, provider records and public-chain verification precisely.
- Carry evaluated template revisions into future context and retain rollback history.
